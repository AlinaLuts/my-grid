# Практична робота 1 (Етап 1): Симуляція стійкості енергосистеми IEEE-118 методом Монте-Карло (MIMD PC)

**Курс:** Грід-системи та хмарні обчислення  
**Архітектурний патерн:** MIMD (Multiple Instruction, Multiple Data) на базі багатоядерного ПК (`multiprocessing.Pool`, чанкування задач, headless-бенчмарк).

---

## 1. Архітектура та фізична модель

Симулятор моделює виникнення та лавиноподібний розвиток каскадних аварій (Blackout) у тестовій високовольтній системі **IEEE-118** (118 підстанцій, 186 ліній електропередач).

```text
[Вихідна мережа IEEE-118] (118 вузлів, 186 ліній у нормальному режимі)
         │
         ▼
[1. Первинний шок N-k] Зважений вибір k ліній за завантаженням (flow / capacity)
         │
         ▼
 ┌───► [2. Перерозподіл потужностей]
 │     Скинутий потік аварійних ліній переходить на сусідні гілки
 │     пропорційно їхньому вільному резерву: reserve = capacity - flow
 │       │
 │       ▼
 │     [3. Перевірка перевантажень]
 │     Чи є активні лінії з flow > capacity?
 │       ├── НІ ──► [СТАБІЛІЗАЦІЯ] (аварія локалізована)
 │       │
 │       └── ТАК ──► Захист вимикає перевантажені лінії (cascade_trips += 1)
 │                   Якщо втрачено > 5% потужності або > 10% ліній ──► [БЛЕКАУТ]
 └─────────────────── Повторити крок 2 (новий крок каскаду)
```

### Патерн MIMD-паралелізму
- Одиниця паралелізму — **незалежні траєкторії (trials)**, а не внутрішні кроки одного каскаду (*embarrassingly parallel*).
- $N$ випробувань розбиваються на рівні пакети (**чанки**) між воркерами.
- Кожен воркер отримує унікальний псевдовипадковий `seed`, що усуває дублювання аварійних сценаріїв.
- Виконання масштабується пулом процесів через `multiprocessing.Pool.map`.

## 3. Інструкція із запуску

### Вимоги
- Python 3.9+
- Бібліотека `matplotlib` (опційно, для побудови графіка `speedup.png`):
  ```bash
  pip install matplotlib
  ```

### Швидкий перевірочний запуск (1 000 випробувань)
```bash
python source/grid-mimd/app.py --trials 1000 --workers 1,2,4
```

### Повний заліковий запуск (10 000 випробувань для звіту)
```bash
python source/grid-mimd/app.py --trials 10000 --k 1
```

### Додаткові параметри CLI
- `--trials` — кількість випробувань Монте-Карло (за замовчуванням: `10000`).
- `--workers` — список кількості воркерів через кому, наприклад: `--workers 1,2,4,8` (за замовчуванням: авто-визначення до `cpu_count()`).
- `--k` — кількість початкових аварійних ліній $N-k$ (за замовчуванням: `1`, валідація: `1 <= k <= 5`).
- `--data` — шлях до каталогу з оригінальним датасетом PowerGraph (якщо відсутній — симулятор прозоро запускає точну автономну топологію IEEE-118).
- `--out` — шлях до вихідного файлу результатів (за замовчуванням: `benchmark_results_mimd_grid.json`).
- `--plot` — шлях збереження графіка (за замовчуванням: `speedup.png`).

## 4. Результати бенчмарку та матеріали для здачі

Після виконання команди `python source/grid-mimd/app.py --trials 10000` скрипт генерує:
1. Консольний звіт із показниками Throughput та Speedup.
2. Файл `benchmark_results_mimd_grid.json`.
3. Графік `speedup.png`.

### Шаблон висновків для здачі в Classroom:
- **Ймовірність блек-ауту $P(\text{blackout})$ для $k=1$:** фіксується у файлі JSON (залежно від вибірки зазвичай становить 0.05–0.09).
- **Продуктивність (Throughput):** демонструє лінійне зростання обчислених траєкторій за секунду при переході від 1 ядра до $N$ ядер.
- **Прискорення (Speedup) та закон Амдала:** прискорення є сублінійним ($S < W$). Це обумовлено накладними витратами на міжпроцесну взаємодію (IPC/pickle) при передачі чанків та зборі результатів, а також послідовною фазою агрегації підсумкових метрик.
- **Топ-3 найвразливіші лінії:** визначаються за частотністю потрапляння в аварійні ланцюги (фіксуються в полі `baseline_top_vulnerable_lines` у JSON).
