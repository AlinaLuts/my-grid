## 1. Список модулів і публічних функцій

### Модуль `source/grid-mimd/engine.py` (Обчислювальне ядро)
- `load_scenario(data_dir, sample_idx=87554) -> GridTopology`:
  - Читання конфігурації топології з файлів `blist.mat`, `Bf.mat`, `Ef.mat`.
  - Вилучення $118$ навантажень шин та $186$ характеристик гілок для конкретного зрізу `sample_idx`.
  - Побудова списків суміжності для миттєвого пошуку сусідніх ліній.
- `run_trial(topology_data, k_fault=1, seed=None) -> TrialResult`:
  - Одне незалежне стохастичне моделювання аварії.
  - Зважений N-k шок, каскадний перерозподіл, фіксація метрик стабілізації/колапсу.
- `simulate_trials_chunk(chunk_args) -> ChunkSummary`:
  - Функція-воркер для процесу в пулі. Виконує пакет випробувань з локальним генератором псевдовипадкових чисел.
- `GridSimulationEngine`:
  - Клас-диспетчер. Керує життєвим циклом пулу процесів, чанкуванням та фінальною редукцією даних.

### Модуль `source/grid-mimd/app.py` (CLI та бенчмарк)
- `parse_args()`:
  - Парсинг параметрів CLI (`--trials`, `--workers`, `--k`, `--sample`, `--data`, `--out`, `--plot`).
- `run_headless_benchmark(engine, config) -> BenchmarkReport`:
  - Серія прогонів для $W \in [1, 2, 4, \dots, \text{cpu\_count}()]$.
  - Вимірювання часу $T_w$, розрахунок Throughput, Speedup $S_w = T_1 / T_w$, знаходження топ-3 уразливих ліній.
  - Експорт звіту в JSON та генерація графічного файлу `speedup.png`.

## 2. Псевдокод ключових алгоритмів (Без Python-коду)

### Псевдокод `run_trial(topology, k_fault, seed)`
```text
АЛГОРИТМ run_trial(Топологія, k_fault, seed):
    Ініціалізувати генератор випадкових чисел від seed
    Скопіювати початкові потоки flow[] та ліміти capacity[] для 186 ліній
    Встановити всі 186 ліній у стан ACTIVE

    1. ПЕРВИННИЙ ШОК (N-k):
       Для кожної лінії розрахувати вагу = (flow / capacity)^2
       Вибрати k_fault унікальних ліній пропорційно їхнім вагам
       Перевести обрані лінії в стан FAILED
       Додати їх до списку Щойно_Вимкнені

    2. ЦИКЛ РОЗВИТКУ КАСКАДУ (поки є Щойно_Вимкнені та крок < 30):
       Для кожної лінії L із Щойно_Вимкнені:
           Скинутий_Потік = flow[L]
           flow[L] = 0
           Знайти всі сусідні лінії біля вузлів u та v, які ще ACTIVE
           Якщо суміжних ліній немає:
               Збільшити втрачене навантаження (вузол знеструмлено)
           Інакше:
               Для кожного сусіда розрахувати вільний резерв = capacity - flow
               Розподілити Скинутий_Потік між сусідами пропорційно їхньому резерву

       Очистити список Щойно_Вимкнені
       Для кожної ACTIVE лінії:
           Якщо flow > capacity:
               Перевести лінію в стан FAILED
               Додати лінію до списку Щойно_Вимкнені
               Збільшити лічильник каскадних відключень

       Якщо Щойно_Вимкнені порожній:
           ЗУПИНКА: мережа успішно стабілізувалася

    3. ПІДСУМОК:
       Розрахувати DNS = Втрачене_Навантаження / Загальне_Навантаження_Мережі
       Блекаут = ТАК, якщо DNS > 0.05 або відключено понад 10% ліній, інакше НІ
       Повернути {Блекаут, Кількість_Відключень, Список_Аварійних_Ліній, DNS}
КІНЕЦЬ АЛГОРИТМУ
```

### Псевдокод `simulate_trials_chunk(chunk_args)`
```text
АЛГОРИТМ simulate_trials_chunk(Розмір_Чанка, k_fault, Базовий_Seed, Топологія):
    Ініціалізувати лічильники: Блекаути = 0, Сума_DNS = 0, Частота_Аварій_Ліній = {}
    
    ДЛЯ i ВІД 0 ДО (Розмір_Чанка - 1):
        Поточний_Seed = Базовий_Seed + i
        Результат = run_trial(Топологія, k_fault, Поточний_Seed)
        
        Якщо Результат.Блекаут == ТАК:
            Блекаути += 1
            Для кожної лінії L із Результат.Список_Аварійних_Ліній:
                Частота_Аварій_Ліній[L] += 1
                
        Сума_DNS += Результат.DNS
        
    Повернути {Розмір_Чанка, Блекаути, Сума_DNS, Частота_Аварій_Ліній}
КІНЕЦЬ АЛГОРИТМУ
```

## 4. Ризики та архітектурні рішення

1. **GIL (Global Interpreter Lock):**
   - *Ризик:* Звичайні потоки (`threading`) у CPython блокуються GIL при інтенсивних обчисленнях на CPU.
   - *Рішення:* Використання виключно `multiprocessing.Pool` (окремі процеси ОС з незалежними адресами пам'яті та власними екземплярами інтерпретатора).
2. **Накладні витрати серіалізації (IPC / Pickle Overhead):**
   - *Ризик:* Передача великих об'єктів графа або повернення $10\,000$ окремих словників через сокети/пайпи сповільнює роботу і знижує Speedup.
   - *Рішення:* Передача компактних числових масивів + повернення лише одного узагальненого словника-агрегата від кожного воркера (4–8 словників замість 10 000).
3. **Розмір датасету та споживання пам'яті (Memory Footprint):**
   - *Ризик:* Повне завантаження всіх $122\,500$ сценаріїв у пам'ять займає ~1.5 ГБ RAM і забирає десятки секунд.
   - *Рішення:* Спрямоване адресне вилучення через HDF5/cell-reference рівно одного обраного індексу ($s = 87554$). Споживання пам'яті — лічені мегабайти.
